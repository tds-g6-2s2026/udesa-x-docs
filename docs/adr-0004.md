# ADR-0004. Python con FastAPI y SQLAlchemy 2.0 sincrónico

- **Estado:** Aceptada
- **Fecha:** 2026-08-11
- **Alcance:** auth, posts, social, media y api-gateway

## Contexto

El equipo necesitaba un stack conocido para avanzar rápido, con validación de datos y documentación de la API sin trabajo extra.

## Decisión

Usamos FastAPI con Pydantic para validar entradas y salidas, SQLAlchemy 2.0 en modo sincrónico, Alembic para las migraciones, PyJWT, argon2-cffi, y Ruff para lint y formato. Cada servicio sigue las mismas capas, con dependencias en una sola dirección:

- **router:** HTTP, rutas, moldes y códigos de estado.
- **service:** reglas de negocio y transacciones.
- **repository:** el único lugar con SQL.

El gateway usa httpx asincrónico, porque su trabajo es reenviar pedidos y esperar respuestas.

## Alternativas

- SQLAlchemy en modo asincrónico.
- Django.

## Consecuencias

A favor:

- El código sincrónico es más simple de leer y de testear a esta escala. Es la razón que deja escrita la guía de auth-service.
- La documentación OpenAPI queda disponible en `/docs` sin trabajo extra.

En contra:

- Cada pedido ocupa un hilo mientras espera a la base. Con más carga habría que medir y, si hace falta, pasar a modo asincrónico.
