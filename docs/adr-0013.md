# ADR-0013. Testing con dependencias inyectadas, base real y mínimo de cobertura

- **Estado:** Aceptada
- **Fecha:** 2026-09-04
- **Alcance:** Todos los backends

## Contexto

La cátedra exige 85% de cobertura unitaria en cada servicio y tests de integración para todas las integraciones del backend, ejecutados en la CI. Los servicios dependen de PostgreSQL, Redis, un servidor de mail y otros servicios.

## Decisión

Las dependencias externas se inyectan con `Depends` de FastAPI: `get_db`, `get_redis` y `get_email_sender`. En los tests se reemplazan así:

- **PostgreSQL:** una base real y dedicada, con una transacción que se deshace al final de cada test.
- **Redis:** fakeredis, un Redis en memoria.
- **Mail:** un EmailSender que no envía nada.
- **Otros servicios:** el cliente HTTP también se inyecta y se reemplaza por uno falso. El gateway simula los servicios con respx.

Los mocks se atan a la interfaz real con `spec`, para que fallen si la interfaz cambia. La CI corre dentro de Docker: Ruff, una prueba de las migraciones que las aplica y las deshace, y los tests, con un mínimo de 85% que hace fallar el pipeline. Las credenciales salen de GitHub Secrets.

## Alternativas

- SQLite en memoria para los tests.
- Mocks sin `spec`.

## Consecuencias

A favor:

- Los tests de integración encuentran errores de SQL y de migraciones que SQLite no mostraría.
- Los backends tienen entre 89,9% y 99,3% de cobertura.

En contra:

- Los tests necesitan un PostgreSQL disponible.
- La app mobile no tiene mínimo de cobertura en su CI y está en 61%. Llevarla a 85% es trabajo pendiente.
