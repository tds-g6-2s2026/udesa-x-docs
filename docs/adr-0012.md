# ADR-0012. Despliegue en el cluster EKS compartido de la cátedra

- **Estado:** Aceptada
- **Fecha:** 2026-10-02
- **Alcance:** Los seis servicios del backend

## Contexto

La cátedra provee un cluster EKS compartido llamado `tds-cluster`, un namespace por grupo con una cuota de 8 pods, un balanceador compartido y CloudFront. La base de datos la tiene que conseguir cada grupo.

## Decisión

- **Un Deployment por servicio,** con una réplica, estrategia Recreate y chequeos de readiness y liveness sobre `/health`.
- **Migraciones al arrancar:** el contenedor corre `alembic upgrade head` antes de levantar uvicorn.
- **Entrada única:** un Ingress manda `/api` al gateway.
- **Pipeline de CD en GitHub Actions:** asume un rol de AWS por OIDC, sin claves guardadas; construye la imagen; la sube a ECR etiquetada con el commit; arma el Secret con GitHub Secrets; aplica los manifiestos y espera el rollout.
- **Fuera del cluster:** PostgreSQL y Redis.

## Alternativas

- Varias réplicas con RollingUpdate.
- PostgreSQL y Redis dentro del cluster.

## Consecuencias

A favor:

- Usa seis pods de ocho, así que queda lugar para un servicio más.
- No hay credenciales de AWS de larga duración.

En contra:

- Recreate deja el servicio sin responder unos segundos en cada despliegue.
- Con una réplica no hay alta disponibilidad.
- El pipeline de CD no vuelve a correr los tests: depende de que la CI haya pasado en el pull request.
