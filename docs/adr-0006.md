# ADR-0006. Sesiones con JWT firmado y revocable

- **Estado:** Aceptada
- **Fecha:** 2026-08-16
- **Alcance:** auth, posts, social y api-gateway

## Contexto

Varios servicios necesitan saber quién hace cada pedido sin consultar a auth en cada llamada. A la vez, las historias exigen poder cerrar sesión y que cambiar la contraseña invalide todas las sesiones abiertas.

## Decisión

auth emite un JWT firmado con HS256 que dura una hora. Lleva tres datos clave: `sub`, el id del usuario; `token_version`; y `jti`, un id único del token.

- **Cerrar sesión** guarda el `jti` en una lista de revocados en Redis hasta que el token vence.
- **Cambiar o restablecer la contraseña** incrementa `users.token_version`. Todo token con una versión anterior deja de valer, en cualquier dispositivo.

posts y social verifican la firma y el vencimiento por su cuenta, con el secreto compartido. La revocación solo la conoce auth, y el gateway la consulta en cada pedido ([ADR-0007](adr-0007.md)).

## Alternativas

- Sesiones guardadas en la base, con un identificador opaco.
- Tokens de acceso cortos más tokens de refresco.

## Consecuencias

A favor:

- Cada servicio verifica el token localmente, sin costo de red.
- Cerrar sesión y cerrar todas las sesiones funcionan sin guardar las sesiones activas.

En contra:

- El secreto HS256 se comparte entre los servicios Python. Si se filtra en uno, se pueden falsificar tokens para todos. La mejora planificada es firmar con clave privada y verificar con clave pública.
- Sin tokens de refresco, la sesión vence a la hora y hay que volver a iniciar sesión.
