# ADR-0009. Paginación por cursor en las listas

- **Estado:** Aceptada
- **Fecha:** 2026-08-31
- **Alcance:** posts y social, y la app

## Contexto

Las listas cambian mientras el usuario las recorre. Con paginación por número de página, que usa OFFSET, si entran posts nuevos se repiten elementos al pedir la página siguiente. Además, OFFSET recorre todas las filas que saltea.

## Decisión

Las listas se paginan con cursor, también llamado keyset. El cliente recibe un cursor opaco que codifica la fecha y el id del último elemento, y la página siguiente pide lo que está antes de ese punto. Cada consulta tiene un índice que coincide con su orden, por ejemplo `(parent_id, created_at, id)` para las respuestas o `(tag, created_at)` para los hashtags. La app recorre las páginas con infinite queries de TanStack Query.

## Alternativas

- Paginación con OFFSET y LIMIT.

## Consecuencias

A favor:

- No hay repetidos ni elementos salteados cuando entran datos nuevos.
- El costo de cada página es el mismo, sin importar cuán lejos esté.

En contra:

- No se puede saltar directo a una página por número.
- Cada lista necesita su índice compuesto.
